Python Logging: A Practical Introduction

Logging gives your Python application a consistent way to record what happened. It becomes especially useful when code runs in servers, scheduled jobs or production systems.

By TechSphere Editorial Team · November 26, 2026 · 6 min read

Why use logging instead of print?

print() is useful when experimenting, but it does not provide built-in severity levels, timestamps or flexible destinations. Python's standard logging module supports these features and is included with Python.

Understand logging levels

  • DEBUG — detailed information useful during development.
  • INFO — normal events showing that the application is working.
  • WARNING — something unexpected happened, but execution can continue.
  • ERROR — an operation failed.
  • CRITICAL — a serious failure may prevent the application from continuing.

Create your first logger

import logging

logging.basicConfig(
    level=logging.INFO,
    format="%(asctime)s %(levelname)s %(name)s: %(message)s"
)

logger = logging.getLogger(__name__)

logger.info("Application started")
logger.warning("Retrying request")
logger.error("Could not process document")

The configured level controls which messages are emitted. With INFO, debug messages are ignored while INFO and higher-severity messages are shown.

Log exceptions with context

try:
    process_document("input.pdf")
except Exception:
    logger.exception("Document processing failed")

logger.exception() records the message and exception traceback. Use it inside an exception handler.

Good logging practices

  • Use a module-level logger with logging.getLogger(__name__).
  • Include useful identifiers such as a job ID when appropriate.
  • Do not log passwords, API keys, tokens or unnecessary personal data.
  • Choose severity levels consistently.
  • Configure handlers and log rotation for long-running applications.
Key takeaway: Good logs explain what happened, where it happened and enough context to investigate — without exposing secrets.
