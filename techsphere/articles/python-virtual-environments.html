Python Virtual Environments: Why and How to Use Them

Virtual environments prevent one Python project’s dependencies from interfering with another. Learn the workflow using Python’s built-in venv module.

By TechSphere Editorial Team · November 26, 2026 · 6 min read

Why do virtual environments matter?

Different Python projects may require different versions of the same package. For example, one application may depend on an older version of a library while another needs a newer release. Installing every package globally can create conflicts.

A virtual environment gives a project its own Python package installation area. It helps make development more predictable and keeps your system Python cleaner.

Create an environment

Open a terminal in your project folder and run:

python -m venv .venv

This creates a folder named .venv. The environment is local to this project. You normally do not commit this folder to Git.

Activate it

On Windows PowerShell:

.venv\Scripts\Activate.ps1

On Windows Command Prompt:

.venv\Scripts\activate.bat

On macOS or Linux:

source .venv/bin/activate

Your terminal prompt usually shows the environment name when it is active.

Install packages

python -m pip install requests pandas

Using python -m pip helps ensure pip belongs to the Python interpreter currently selected in the terminal.

Save dependencies

When your project is ready to share, record its installed packages:

python -m pip freeze > requirements.txt

Another developer can install the listed packages in their own environment:

python -m pip install -r requirements.txt

For production projects, consider maintaining intentional dependency constraints rather than blindly freezing every package in a development environment.

Deactivate and ignore

Run deactivate to leave the environment. Add this line to your .gitignore file:

.venv/

Common mistakes

  • Installing packages before activating the environment.
  • Using a different interpreter in your editor than in your terminal.
  • Committing the entire .venv folder to Git.
  • Forgetting to document dependencies for other developers.
Remember: Create one virtual environment per project, activate it before installing packages, and record the dependencies needed to reproduce the setup.
