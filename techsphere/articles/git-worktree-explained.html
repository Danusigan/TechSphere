Git Worktree Explained: Work on Multiple Branches

Git worktree lets you work with multiple branches at the same time without repeatedly switching the branch in one folder.

By TechSphere Editorial Team · November 26, 2026 · 5 min read

What is a Git worktree?

A Git worktree is an additional working directory connected to the same local repository. Each worktree can have a different branch checked out. Your repository history and objects are shared, while each worktree has its own files and working state.

Why use it?

Suppose you are implementing a feature on a branch, and a production bug needs an urgent fix on another branch. You can create a second worktree for the hotfix instead of stashing changes or repeatedly switching branches.

Useful commands

List existing worktrees:

git worktree list

Create a worktree for an existing branch:

git worktree add ../project-hotfix hotfix/login

Create a new branch and worktree:

git worktree add -b feature/search ../project-search

Remove a worktree after you finish with it:

git worktree remove ../project-hotfix

Important rules

  • A branch generally cannot be checked out in two worktrees at the same time.
  • Keep worktree folders organized so you know which task each one represents.
  • Commit or otherwise preserve changes before removing a worktree.
  • Use git worktree prune to clean up stale worktree metadata when necessary.

Example workflow

  1. Keep your main project folder on the feature branch.
  2. Create a sibling folder for the hotfix branch.
  3. Open each folder in a separate editor window.
  4. Test and commit each change in its own worktree.
  5. Remove the extra worktree when the task is complete.
In short: Git worktree is useful when you need parallel working directories. It does not create a separate clone of the full repository history.
